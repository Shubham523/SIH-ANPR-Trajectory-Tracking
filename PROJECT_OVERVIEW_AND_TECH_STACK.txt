1. EXECUTIVE SUMMARY & PROBLEM STATEMENT
================================================================================
Smart India Hackathon (SIH) Problem Statement: 26127
Project Name: City-Wide AI Engine for Multi-Camera ANPR Trajectory Tracking

The Challenge:
Traditional CCTV tracking systems operate within a single camera's field of view.
When a vehicle exits the camera's sight, its identity is lost. In a real-world
city, cameras are separated by hundreds of meters of "blind spots" (non-overlapping
fields of view). 

Furthermore, real-world license plates are often:
- Obscured by mud, rain, darkness, or high vehicle speeds.
- Intentionally tampered with, fake, or missing.
- Blurry due to motion blur or low-resolution camera sensors.

The Solution:
This project builds a distributed, real-time AI engine that maintains a persistent
"Global Vehicle Identity" as vehicles travel across disparate cameras in a city.
It solves the blind-spot and occlusion problems by performing "Decision Fusion":
combining Automatic Number Plate Recognition (ANPR) with deep visual Vehicle
Re-Identification (Re-ID embeddings) and Spatiotemporal Feasibility Verification.

================================================================================
2. HOW TO EXPLAIN THIS PROJECT IN SIMPLE TERMS (ELEVATOR PITCH)
================================================================================
"Imagine police are looking for a suspect car across a smart city with 5,000
cameras. In standard systems, if the license plate is covered in dirt or the car
drives between camera blind spots, the trail goes cold.

Our system creates a digital fingerprint for every vehicle. It reads the plate
if visible, but simultaneously captures a 512-dimensional visual vector of the
car's unique shape, color, aspect ratio, and features. Even if the car passes
Camera 2 with a completely obscured or illegible plate, our AI compares the visual
fingerprint against recently seen vehicles, checks if the transit time between
those two physical intersections is physically possible, and automatically connects
the dots into a single chronological trajectory on an interactive city map."

3. END-TO-END SYSTEM WORKFLOW (STEP-BY-STEP)
================================================================================

[STEP 1: Video Ingestion at the Camera (Edge)]
  - The system receives RTSP/IP camera streams or video files from traffic nodes.

[STEP 2: Vehicle Detection]
  - YOLOv8 Nano processes incoming frames using FP16 mixed precision.
  - Bounding boxes are drawn around cars, buses, trucks, and two-wheelers.

[STEP 3: Local Frame-to-Frame Tracking]
  - ByteTrack / IoU tracker monitors the vehicle while it stays inside the camera's
    view, assigning a temporary local tracking ID (e.g., Local ID #42).

[STEP 4: Feature Extraction (Dual-Branch)]
  - Branch A (ANPR OCR): Crops the lower plate region and runs OCR text
    extraction, outputting plate alphanumeric text and an OCR confidence score.
  - Branch B (Visual Re-ID): Passes the full vehicle crop through a deep feature
    extractor, outputting a 512-dimensional normalized numerical vector.

[STEP 5: Lightweight Event Publishing]
  - Instead of streaming heavy raw video across the city network, the edge node
    publishes a lightweight JSON event payload (Camera ID, Timestamp, Local ID,
    Plate Text, Confidence, and the 512-dim Vector) to the central message bus.

[STEP 6: Central Brain Ingestion (EventBus)]
  - FastAPI asynchronous event bus consumes incoming messages from all camera
    nodes with zero backpressure.

[STEP 7: Fused Global Trajectory Matching]
  - The Central Matcher queries active vehicles in memory:
    a) Compares license plates using normalized Levenshtein edit distance.
    b) Compares visual vectors using Cosine Similarity.
    c) Checks Spatiotemporal Feasibility: Calculates the physical distance
       between cameras using the Haversine formula and checks if the transit
       speed is physically possible (e.g., <= 140 km/h).
    d) Fuses the scores. If a match is found, links the detection to an existing
       Global Vehicle ID (e.g., GID-20260912-1002); otherwise, registers a new one.

[STEP 8: Storage & Real-Time Broadcasting]
  - The trajectory waypoint (Global ID, Camera, Coordinates, Timestamp, Speed)
    is saved to the time-series database.
  - Instant WebSocket broadcast pushes the live detection to connected operators.

[STEP 9: Operator Dashboard Visualization]
  - The React GIS Map dynamically plots the vehicle's chronological polyline route.
  - The Live Hits column displays real-time detection cards with color-coded tags.
  - Operators can search by plate, inspect waypoint hops, and monitor GPU health.

4. TECH STACK BREAKDOWN & RATIONALE (WHY EACH TOOL WAS CHOSEN)
================================================================================

--------------------------------------------------------------------------------
4.1 EDGE COMPUTER VISION & ML PIPELINE
--------------------------------------------------------------------------------
* PyTorch (v2.7+ CUDA 11.8/13.1):
  - Rationale: Industry-standard deep learning framework with native Windows
    and Linux GPU acceleration. Enables FP16 mixed precision to halve memory.

* YOLOv8n (Nano) / YOLOv10:
  - Rationale: Ultra-fast real-time object detection (~3-6ms per frame).
    The 'Nano' variant has a tiny footprint (<15MB weights), allowing it to
    run comfortably within the 6GB VRAM limit of an NVIDIA RTX 3050 GPU.

* ByteTrack / IoU Tracking:
  - Rationale: Low-latency frame-to-frame association. Keeps local vehicle IDs
    consistent as vehicles move through occlusions inside a single camera view
    without needing heavy recurrent neural networks.

* ANPR OCR Engine:
  - Rationale: Extracts alphanumeric text from cropped plate regions with
    regex validation for standard Indian license plate formats (e.g. DL-01-AB-1234).

* Vehicle Re-Identification (Re-ID) Engine:
  - Model: Deep Convolutional Feature Extractor (OSNet / ResNet architecture).
  - Output: 512-dimensional L2-normalized vector embedding.
  - Rationale: When plates are covered in mud, obscured by bright headlight glare,
    or blurry, this vector captures holistic visual characteristics (body geometry,
    color distribution, roof racks, vehicle type) for cross-camera matching.

--------------------------------------------------------------------------------
4.2 CENTRAL BRAIN & BACKEND SERVICES
--------------------------------------------------------------------------------
* FastAPI (Python 3.10):
  - Rationale: One of the fastest Python frameworks available. Built on ASGI
    and Starlette, natively asynchronous (async/await), automatic OpenAPI/Swagger
    documentation generation, and built-in WebSocket support.

* Uvicorn (ASGI Web Server):
  - Rationale: Lightning-fast production server for Python async applications,
    supporting high concurrency with minimal CPU and memory overhead.

* Pydantic v2:
  - Rationale: High-performance data validation and serialization powered by
    a Rust core (pydantic-core), ensuring strict type safety for JSON events.

--------------------------------------------------------------------------------
4.3 MESSAGE BROKER & EVENT STREAMING
--------------------------------------------------------------------------------
* In-Memory Async EventBus (MVP) + Apache Kafka (KRaft Mode for Production):
  - Rationale: Streaming raw video to a central server crashes networks. By
    running ML at the edge and streaming only lightweight JSON events, network
    bandwidth drops by >98%. Kafka's distributed pub-sub model queues bursts
    during rush hour traffic without dropping frames or blocking the database.

--------------------------------------------------------------------------------
4.4 TIME-SERIES & GEOSPATIAL DATA LAYER
--------------------------------------------------------------------------------
* SQLite with Write-Ahead Logging (WAL Mode) for Local / MVP Execution:
  - Rationale: Zero configuration, zero external service dependency, instantaneous
    portability on Windows, and handles thousands of reads/writes per second.

* TimescaleDB + PostGIS (Docker Production Configuration):
  - Rationale: Vehicle trajectories are fundamentally time-series data
    (Location X at Time Y). TimescaleDB partitions data into automatic time
    hypertables, accelerating time-range filtering by up to 100x compared to
    vanilla relational databases. PostGIS provides geospatial distance queries.

--------------------------------------------------------------------------------
4.5 FRONTEND DASHBOARD & OPERATOR CONSOLE
--------------------------------------------------------------------------------
* React 18 + Vite:
  - Rationale: Component-based architecture with sub-second HMR development and
    highly optimized production chunk splitting (18s production build).

* Tailwind CSS:
  - Rationale: Utility-first CSS allowing total control over styling.

* Design Philosophy: Utilitarian Flat Brutalism (Per SIH Reference Guidelines):
  - What is strictly avoided: Neon glows, gradients, rounded pills, glassmorphism.
  - What is used: Solid high-contrast colors (slate-900, slate-100, emerald-600,
    amber-500, yellow-200 for plates), 1px solid borders, sharp corners, and
    monospace typography (JetBrains Mono) for plates, timestamps, and coordinates.
  - Reason: Long monitoring shifts by police/traffic operators require zero eye
    strain and high information density, looking like a heavy-duty command tool
    rather than a toy consumer app.

* Leaflet GIS:
  - Rationale: Lightweight, open-source geospatial mapping library that renders
    custom square camera markers, moving vehicle indicators, and trajectory
    polylines smoothly without heavy third-party API dependencies.

5. CORE ALGORITHMIC NOVELTY: FUSED TRAJECTORY MATCHING ENGINE
================================================================================
The primary intellectual contribution of this project is the Fused Trajectory
Matching Engine (located in `backend/app/core/trajectory_matcher.py`):

1. Plate Text Similarity (Levenshtein Distance):
   S_plate = 1 - (Levenshtein(Plate_A, Plate_B) / MaxLength)
   Normalizes text match between 0.0 and 1.0, handling character typos
   (e.g., 'O' vs '0', 'B' vs '8').

2. Visual Re-ID Embedding Similarity (Cosine Similarity):
   S_reid = (V_1 . V_2) / (||V_1|| * ||V_2||)
   Computes the angular similarity between two 512-dim visual vectors.

3. Dynamic Confidence Fusion:
   Score = (Alpha * S_plate) + ((1 - Alpha) * S_reid)
   - When the plate is crystal clear (confidence > 0.9), Alpha is high (~0.8),
     giving priority to the alphanumeric plate.
   - When the plate is blurry, occluded, or absent, Alpha drops, allowing the
     visual Re-ID vector to automatically take over (REID_FALLBACK).

4. Spatiotemporal Feasibility Verification (Anti-Spoofing):
   Distance = Haversine(Lat1, Lon1, Lat2, Lon2)
   Velocity = Distance / Delta_Time
   - If a detection claiming to be the same vehicle appears at Camera 4 only
     1 second after Camera 1 (calculated speed > 140 km/h), the match is
     REJECTED as physically impossible. This eliminates false positive matches
     and cloned plate spoofing.

6. FUTURE SCOPE & REAL-WORLD SCALABILITY (10,000+ CAMERAS)
================================================================================

1. Edge Computing Gateways (NVIDIA Jetson Deployment):
   - In production, YOLO + Re-ID runs on small NVIDIA Jetson Orin Nano modules
     mounted directly on CCTV poles.
   - Only 200-byte JSON messages travel over 4G/5G backhauls, eliminating the
     need to transmit costly raw 4K video feeds to central servers.

2. Vector Database Integration (Milvus / Qdrant / Pgvector):
   - As active tracks scale to 500,000+ vehicles across a metropolitan city,
     linear cosine comparisons become computationally expensive.
   - Using HNSW (Hierarchical Navigable Small World) indexing in Milvus/Qdrant
     enables sub-5 millisecond vector nearest-neighbor searches across millions
     of vehicle embeddings.

3. Graph Neural Networks (GNNs) for Predictive Trajectory Tracking:
   - Modeling the city's road network as a directed graph where intersections
     are nodes and roads are edges.
   - Given a suspect vehicle's current trajectory, GNNs can predict with high
     probability which camera intersection the vehicle will cross next.

4. Law Enforcement & Emergency Dispatch Integration:
   - Automated Hotlist / Blacklist triggers: Instant push notifications when
     a stolen or wanted vehicle is detected.
   - Red Light Violation & Wrong-Way Driving trajectory flagging.
   - Green Corridor Automation: Dynamically clearing traffic signals for
     approaching ambulances by tracking emergency vehicle trajectories.
